# Development workflow

1. Read the assignment and place its acceptance criteria in the working task
   report. Inspect the local branch, status, and existing changes.
2. Start one local branch per assignment from an approved committed baseline.
   Use `feat/merchant-catalogue-inventory` for the merchant assignment once its
   implementation plan is agreed.
3. Keep the branch scoped to its assignment. Record decisions, test results, and
   any dependencies on other branches.
4. Prepare a handoff with an acceptance-criteria checklist, the change summary,
   test evidence, and any remaining caveats. Verify the diff before requesting
   authorization for a commit.
5. When a GitHub destination and base are confirmed, prepare the assignment
   diff against that base. The developer publishes the branch, opens the
   GitHub PR, and submits the PR link and summary on the assignment page.
